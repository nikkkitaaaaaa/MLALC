    🔢 Module 3 — LU Decomposition Engine

    "Every system of equations hides two triangles. LU decomposition finds them."

    🎓 Mathematical Foundation

    Problem: Solve Ax = b — given matrix A and vector b, find x.

    Insight: Triangular systems are trivially solvable. If we can factor A = LU, then:

    A x = b
(LU) x = b
L (Ux) = b

    Let y = Ux. Then: 1. Solve Ly = b → forward substitution (top to bottom) 2. Solve Ux = y → backward substitution (bottom to top)

    Where L and U come from: 

    L = lower triangular     U = upper triangular
[1  0  0]                [u00 u01 u02]
[l10 1  0]               [0   u11 u12]
[l20 l21 1]              [0   0   u22]
    L has 1s on the diagonal. U is what Gaussian elimination produces.

    Partial pivoting adds a permutation: PA = LU. We reorder rows of A to put the largest element in the pivot position — this avoids division by tiny numbers that cause numerical explosion.

    🔍 Step-by-Step Decomposition

    Worked Example

    A = [2  1  1]
    [4  3  3]
    [8  7  9]

    Step k=0: Largest in column 0 is 8 (row 2). Swap rows 0 and 2. 

    U = [8  7  9]    p = [2, 1, 0]
    [4  3  3]
    [2  1  1]
    Factor: l10 = 4/8 = 0.5, l20 = 2/8 = 0.25. Eliminate: 
    U = [8   7    9  ]
    [0  -0.5 -1.5]
    [0  -0.75 -1.25]

    Step k=1: Continue elimination... final result: 

    L = [1     0    0]    U = [8   7    9   ]
    [0.5   1    0]        [0  -0.5 -1.5 ]
    [0.25  0.5  1]        [0   0   0.5  ]

    🧠 Memory Perspective

    The code initializes U as a copy of A, then modifies it in-place:

    memcpy(u->data, a->data, n * n * sizeof(double));  // U starts as A

    Smart memory trick: inv_pivot = 1.0 / u_data[k*n+k]

    Instead of dividing by the pivot element for every row below, compute the reciprocal once and multiply. Division is ~20-30 CPU cycles; multiplication is ~3-5 cycles. For n=500, this saves 500*500/2 ≈ 125,000 divisions replaced by multiplications. 🚀

    Row swap uses memcpy: 

    memcpy(temp, row1, m->cols * sizeof(double));
memcpy(row1, row2, m->cols * sizeof(double));
memcpy(row2, temp, m->cols * sizeof(double));
    Three bulk copies beat n element-wise swaps for large n.

    ⚡ Optimization Journey

    The Inner Loop

    double *row_i = u_data + i * n;   // pointer to row i
double *row_k = u_data + k * n;   // pointer to pivot row k

for(int j = k; j < n; j++)
    row_i[j] -= factor * row_k[j];  // sequential! ✅

    Both row_i and row_k are accessed sequentially. The CPU prefetcher loves this. factor is a scalar in a register — the multiply-subtract in the inner loop is the tightest possible form.

    Complexity

    • LU decomposition: O(n³/3) — the dominant cost
    • Forward/backward substitution: O(n²) each — cheap!
    • Once you have L and U, solving for a different b costs only O(n²). Huge win if you solve the same system with multiple right-hand sides.

    😂 Meme Explanation

    You: "Solve this 1000×1000 system of equations"

LU Decomposition: "Pay me O(n³) once, ask me 1000 times for O(n²) each"
You: "You're hired"
LU: "Also I need partial pivoting or I'll explode numerically"
You: "...sure"

    🧙 Numerical Recipes Wisdom

    "Never solve Ax=b by computing A⁻¹. Never. Ever."

    Computing the inverse costs 3x the operations of LU and accumulates more floating-point error. The LU solve path (lu_decompose + substitution) is both faster and more numerically stable.

    Also: partial pivoting is not optional. Without it, a zero pivot causes division by zero. With it, the algorithm is backward stable — errors stay proportional to machine epsilon. This library implements partial pivoting correctly. ✅
