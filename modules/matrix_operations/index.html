    ➕ Module 2 — Matrix Operations Engine

    "You can't do science without addition. You can't do it fast without understanding your cache."

    🎓 Mathematical Foundation

    Four core operations this module provides:

    Operation Math Condition
    Addition C = A + B A, B same shape
    Subtraction C = A - B A, B same shape
    Scalar multiply C = s * A any matrix
    Matrix multiply C = A × B A.cols == B.rows

    Matrix multiply is where the real action is — and where 90% of the optimization effort goes in scientific computing.

    🔍 Behind The Code

    Add & Subtract — Flat Loop Trick

    matrix* matrix_add(const matrix *restrict a,
                   const matrix *restrict b) {
    int total = a->rows * a->cols;

    const double *ad = a->data;  // raw pointer
    const double *bd = b->data;
    double *rd = r->data;

    for(i = 0; i < total; i++)
        rd[i] = ad[i] + bd[i];  // treat 2D as 1D
}

    Key insight: Instead of MAT(a,i,j) with two index variables, we flatten the 2D matrix into a 1D array and loop once over total = rows * cols elements.

    What the CPU sees: A perfectly sequential memory access pattern — every element is adjacent in memory. This is the most cache-friendly loop possible. The CPU's prefetcher predicts the pattern and loads ahead. ⚡

    The restrict keyword: Tells the compiler "I promise a, b, and r don't overlap in memory." This allows the compiler to generate vectorized (SIMD) code — processing multiple doubles per CPU instruction.

    Scalar Multiply

    for(i = 0; i < total; i++)
    rd[i] = ad[i] * s;

    Identical pattern — sequential, cache-friendly, SIMD-friendly. The compiler can auto-vectorize this to process 4 doubles at once with AVX2.

    Matrix Multiply — The Interesting One

    Naïve implementation: 

    // SLOW - cache-unfriendly
for(i=0; i<m; i++)
  for(j=0; j<p; j++)
    for(k=0; k<n; k++)
      C[i][j] += A[i][k] * B[k][j];  // B[k][j] jumps columns!

    This library's implementation (i-k-j order): 

    for(i=0; i<m; i++) {
    double *rowC = cd + i*p;        // pointer to row i of C
    const double *rowA = ad + i*n;  // pointer to row i of A

    for(k=0; k<n; k++) {
        double aik = rowA[k];           // scalar: A[i][k]
        const double *rowB = bd + k*p;  // pointer to row k of B

        for(j=0; j<p; j++)
            rowC[j] += aik * rowB[j];   // sequential access ✅
    }
}

    ⚡ Optimization Journey

    Why Loop Order Matters

    Memory layout of B (row-major):
Row 0: [B00, B01, B02, B03]   ← adjacent in memory
Row 1: [B10, B11, B12, B13]
Row 2: [B20, B21, B22, B23]

i-j-k order accesses B[k][j]:
  k=0,j=0 → B[0][0]   (cache hit)
  k=1,j=0 → B[1][0]   ← jumps 4 elements! (cache miss)
  k=2,j=0 → B[2][0]   ← another jump (cache miss)

i-k-j order accesses B[k][j]:
  k=0,j=0 → B[0][0]   (cache hit)
  k=0,j=1 → B[0][1]   ← next element! (cache hit)
  k=0,j=2 → B[0][2]   ← next element! (cache hit)

    The i-k-j order keeps rowB hot in cache. The scalar aik = A[i][k] is hoisted outside the inner loop — it's the same value for the entire j-loop, stored in a register.

    Pointer Arithmetic vs Array Indexing

    double *rowC = cd + i*p;   // compute offset ONCE per row
rowC[j] += ...;             // cheap: just pointer + j

// vs
c->data[i*p + j] += ...;   // compute i*p every single inner loop iteration

    By computing row pointers once, we eliminate a multiply from the inner loop. On a 1000×1000 multiply, that's 10⁹ multiplications saved.

    🧙 Numerical Recipes Wisdom

    "The innermost loop is sacred. Every unnecessary operation there costs you dearly."

    Three rules for fast matrix code: 1. Access memory sequentially — rows in row-major order 2. Hoist invariants — if aik doesn't change in the j-loop, compute it once outside 3. Use restrict — let the compiler generate SIMD; you don't have to write intrinsics

    This library follows all three. The result is code that runs 3-5x faster than the naïve version on modern hardware, with zero external dependencies.
